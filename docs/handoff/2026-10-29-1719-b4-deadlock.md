## Current issue (M-003)
In `BookingConcurrencyIT` one request gets `201` (no double booking), the other 19 get `500`. The appointment INSERT fails with `40P01 deadlock detected`: with a GiST exclusion constraint PostgreSQL inserts the index entry first and checks afterwards, so two concurrent conflicting inserts wait for each other. Detection takes `deadlock_timeout` (1 s), so the test also takes about 20 s. ADR-003, FR-2.8 and AGENTS.md §5 assume only `23P01`.

## Decisions made (and why)
- Booking attempt = own `TransactionTemplate` (REQUIRES_NEW) with customer/vehicle resolution + insert (FR-3.3, AGENTS §5).
- Insert via JDBC so the `PSQLException` constraint name maps the conflict (bay, technician, vehicle, idempotency key).
- After a bay/technician conflict only that resource advances (`AssignmentPlan`); vehicle conflict and explicit-resource conflict are not retried.
- 409 bodies carry `conflict.resource` (FR-2.7).
